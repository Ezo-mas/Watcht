# Architecture guide — read before touching load-bearing code

Read this before changing `internal/db/`, `internal/tracking/`,
`internal/auth/`, `internal/jobs/`, migrations, or the HTTP API shape. The
full design is in [rewrite-plan.md](../rewrite-plan.md); this guide lists
the invariants that are easy to break by accident.

## Package dependencies

```
cmd/watcht → httpapi → catalog, tracking, auth, jobs, importers, providers/*
                         ↓
                       db, db/sqlc
```

Dependencies point down only. Domain packages never import `httpapi`.
Providers return plain Go structs; they don't write to the database
themselves. `catalog` and `tracking` decide what gets stored.

## Invariants

1. **Database access goes through `internal/db`.** It opens two handles:
   a write pool with exactly one connection and a read pool. Both apply
   `journal_mode=WAL`, `foreign_keys=ON`, `busy_timeout=5000`, and
   `synchronous=NORMAL` on every connection. Don't open SQLite anywhere
   else, and don't run writes on the read pool. A write on the read pool
   bypasses the single writer and brings back `SQLITE_BUSY` errors.
2. **Migrations.** Goose `.sql` files in `internal/db/migrations/`,
   embedded and applied at startup after a pre-migration `VACUUM INTO`
   backup. Before v0.1.0 the baseline can be rewritten. From v0.1.0 on,
   released migration files are never edited; changes are new files.
   Tables are `STRICT`.
3. **Generated code.** `internal/db/sqlc/` is generated by `make generate`
   from `internal/db/queries/*.sql`. Never hand-edit it; CI fails if it's
   stale.
4. **Time.** Store UTC RFC 3339 text. Convert to the user's IANA time zone
   only when grouping by day or formatting. Day-boundary logic lives in one
   helper with tests for DST changes.
5. **Episode identity.** The TMDB episode ID is the identity. Season and
   episode numbers are display data that metadata refresh can change.
   Matching from imports or media servers resolves to a TMDB episode ID
   first; unresolved items go to a review list, never a guess.
6. **Watch events.** Only `internal/tracking` inserts into `watch_events`.
   It applies, in order: the completion rule (85% or marked played), source
   idempotency (unique user + source + source_event_id), and dedupe (same
   user and item within the window counts once; later events are recorded
   as merged, not dropped). Unplaying an item on a media server doesn't
   delete history.
7. **Progress and stats are derived** from `watch_events`, `episodes`, and
   `seasons` by query. There are no progress tables to keep in sync.
8. **Jobs.** Webhook handlers validate, store the raw event, enqueue a job,
   and return `202`. Long or retryable work runs in the job worker, never
   in a request handler.
9. **Auth.** Session and API tokens are random, stored as SHA-256 hashes,
   and compared in constant time. Passwords use argon2id. Every non-GET
   request passes the `Origin` check. See `SECURITY.md` before changing
   any of this.
10. **HTTP API.** Routes under `/api/v1`, JSON only, one error shape.
    Anything not under `/api/`, `/healthz`, or a built asset returns the
    SPA's `index.html`, except missing files under `/_app/`, which 404 so
    a stale tab never receives HTML as JavaScript.

## Known pitfalls

- `modernc.org/sqlite` is pure Go. Never add `mattn/go-sqlite3` or any
  other CGO dependency; the Docker build uses `CGO_ENABLED=0` and will fail.
- SQLite has foreign keys off by default. Tests that open a database
  without `internal/db` won't enforce them and can pass when they shouldn't.
  Always use the test helper.
- `VACUUM INTO` needs a target path that doesn't exist yet; the backup code
  generates unique names.
- Don't copy the live database file for backups or tests while the server
  is running.
